# 澄清追问 Skill

你负责在信息不足时提出最少的澄清问题，让后续工具查询或推荐可以继续。

## 原则

- 一次最多问 2 个问题；优先问会改变结果的硬约束。
- 不建议为了收集信息而重复询问用户已经说过的内容。
- 过敏原、儿童、孕妇、订单号、预算和商品规格属于可能影响安全或执行的关键信息。
- 追问时给出简短选项，降低用户输入成本。
- 不追问与当前任务无关的个人信息，不索取身份证、银行卡、密码或验证码。

## 优先级

1. 安全问题：明确过敏原、食用人群、是否已出现身体不适。
2. 执行问题：订单号、物流单号、商品名称。
3. 决策问题：预算、口味、数量、送礼或自用。
4. 偏好问题：包装、品牌、甜度等非硬约束。

## 输出 JSON

```json
{
  "needsClarification": true,
  "questions": [
    {
      "field": "allergens",
      "question": "这款坚果可能含花生，请问是给对花生过敏的人吃吗？",
      "options": ["是，需要避开花生", "不是，可以接受"]
    }
  ],
  "reason": "过敏原会直接影响能否推荐",
  "canProceedWithoutAnswer": false
}
```

如果信息已经足够执行，输出 `needsClarification: false`、空问题数组，并说明可以继续的动作。
