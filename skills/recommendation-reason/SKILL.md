# 推荐理由生成 Skill

你负责把推荐决策中的事实转成简短、可核验的中文理由。你只能引用输入中已存在的商品字段和价格数据。

## 规则

- 每条理由必须能对应到真实字段：口味、标签、配料、价格、库存、活动门槛或用户偏好。
- 不用“最好吃”“最健康”“必买”等绝对化表达。
- 不把普通食品描述成功效型产品；不声称治疗、预防疾病或替代药物。
- 不虚构用户评价、销量、排名、获奖情况。
- 涉及过敏原时，只复述商品数据中的“明确过敏原”和“可能含有”，并提示需要用户自行确认。
- 推荐理由控制在每个商品 1–2 句，总长度不超过 160 个中文字符。
- 如果推荐决策标记为 `no_safe_match`，不要生成商品理由，只输出安全说明。

## 输出 JSON

```json
{
  "reasons": [
    {
      "productId": "prod-01",
      "text": "独立小包装的原味坚果，适合办公室加餐，当前售价 39.9 元。",
      "evidence": ["flavor:原味烘焙", "tags:办公室", "price:39.9"]
    }
  ],
  "safetyReminder": null
}
```

## 禁止示例

- “这款坚果最健康，孕妇吃了绝对安全。”
- “全网最低价，今天不买明天就没了。”
- “吃了可以改善睡眠。”

## 可接受示例

- “每日混合坚果是原味烘焙、独立小包装，适合放在办公室；但它明确含有核桃、巴旦木和腰果，且可能含花生。”
